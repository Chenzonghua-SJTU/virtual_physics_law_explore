# 网页运行物理规律探索

网页连接当前项目的 Python Agent，执行真实的模型调用、实验、拟合、验证和提交。实验计算发生在本机，模型请求默认发送至 DeepSeek API，也可配置为本地部署的服务。

## 启动

在项目目录打开终端：

```bash
.venv/bin/python -m shore_agent.web --port 8765
```

打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)。启动终端保持运行；按 `Ctrl+C` 关闭服务，同时停止由它启动的探索进程。如果端口被占用，可改成 `--port 8766`，浏览器访问对应端口。

新环境先按 [README](../README.md) 安装依赖。网页沿用项目的 NumPy、SciPy 和 HTTP 客户端；不需要 Node.js、前端打包或 CDN。单独双击 `web/index.html` 无法调用本地 Agent，需要通过上述服务访问。

本地部署时，用服务端配置指定 API 地址、模型名称和推理参数协议：

```bash
.venv/bin/python -m shore_agent.web --port 8765 --config config.local.example.json
```

`--config` 的 JSON 字段覆盖 `config.example.json` 同名配置段中的字段；未指定的字段沿用默认值。网页从该有效配置读取默认预算、推理强度、世界等设置。显式指定配置文件时，模型下拉框仅提供该配置的 `model.model`；浏览器不能覆盖 `base_url`、认证策略或推理协议。`model.api_key_env` 可指定密钥环境变量；仅显式本地部署且地址为回环地址时，才允许 `model.api_key_required=false`，页面会相应提示无需密钥。部署程序仍需支持配置的推理协议，选择档位并不自动证明服务端实际采用了该档位；映射和本地验证方法见 [README](../README.md)。更新后台代码后需重启服务。

## 运行一次探索

1. 输入 DeepSeek API Key。若启动服务前已设置 `DEEPSEEK_API_KEY` 环境变量，页面会提示已配置，可留空输入框。
2. 选择世界 01–07、模型、噪声模式与随机种子；在「高级设置」中可开关思考模式、选择推理强度「低 low／高 high／最高 max」、调整总 token 预算和单次输出上限。默认世界为原始世界 01，其余默认参数与项目配置一致：开启思考、低强度、无噪声、种子 42、总 token 上限 5,000,000、单次输出上限 65,536（含思考、正文与工具参数）。模型调用次数和对话总轮次不设上限，页面保留实际调用计数。推理强度仅在思考模式开启时生效；更高档位可能增加时间和用量，探索质量仍需根据验证结果判断。
3. 点击「开始探索」。每次会生成独立的 `runs/web-时间-随机编号/` 目录，不覆盖已有结果。
4. 查看持续更新的研究进展、工具调用、实验能量、探针轨迹和规律记录。工具失败、预算耗尽或模型没有提交时，页面会保留相应状态，不伪造成功结果。
5. Agent 成功提交且会话已结束后，后台自动执行独立评测，默认使用 20 条未见初态。完成后可查看指标并导出公开结果 JSON。

「停止本次探索」会终止当前探索的工作进程及其计算子进程，已经保存的记录保留。调用已发出时停止不能撤销服务商已发生的用量。停止之后需要开启一次新探索；当前版本不支持从中断处继续 Agent 会话。

同一服务同时只运行一次探索。关闭或刷新网页不等于停止后台任务；重新打开网页可继续观察当前运行。历史列表也能查看之前通过命令行生成的档案。历史结果标明自主探索、手工工程测试、分析诊断或未核验历史，便于区分来源。

每次会话固定在启动时选择的世界，运行中不能更改。历史列表、详情和回收站显示所属世界，旧会话默认归入世界01。世界06增加源运动，世界07增加固定源下的周期强度变化；其余观测和预算规则一致。Agent只收到中性世界编号，不收到开发者的真实公式。详见[七世界说明](worlds.md)。

已结束的历史会话可以删除，删除后进入回收站，原始文件保留；在回收站点击恢复可重新放回历史列表。正在运行或评测的会话禁止删除，需要先停止或等待结束。删除和恢复都不会启动模型，也不会消耗 API 额度；如果原位置已有同名会话，恢复会报告冲突而不会覆盖它。

若页面报告「模型回复达到输出上限」，本次会话会以未完成结束，不执行截断的工具参数。可在高级设置中关闭思考模式后开启新会话；原失败档案会保留。总 token 预算与单次回复上限不同，调大总预算不改变单次回复上限。

## 结果与科学边界

v4新会话恢复题目规定的已知t=0初态及免费第一束光天体位置。轨迹图显示已取得的天体位置序列，支持选择绝对时间；菱形是选定时刻的观测插值，覆盖范围外不画推测坐标。追加观察按时间补充轨迹，不将移动轨迹平均为一个静止位置。候选详情标记冻结的训练观测版本；当前源位置与训练输入有差异时，可在训练覆盖范围内查看空心标记。力场公式与参数保持冻结，新验证单独保存当次使用的合法源观测。前端不会补入未来真实位置。旧v1–v3档案仍按原静态观测与冻结位置语义展示，原始law和评测不重写。

新探索提交时必须同时给出 `physical_explanation`。最终答案增加「物理解释」区域，显示 Agent 对公式各项、参数、实验依据及不确定性的解释，标明对应的最终提交版本；切换其他候选规律不会将这段解释误标为该候选的解释。旧会话显示「该历史会话未提交物理解释」，不会自动补写。解释随公开结果 JSON 导出，也保存在提交目录的 `physical_explanation.txt` 中。格式受理和数值评测不自动验证解释的科学正确性。

轨迹图来自已保存的合法探针观测；规律和验证数据来自七个科学工具的记录。新探索已移除分析子 Agent 和 summarize_data 工具，主 Agent 直接完成数据解释与研究决策。网页只负责操作和展示，不向模型增加文件、Shell 或真值访问。历史会话仍可显示旧版分析步骤和原始错误。

自动评测在主 Agent 返回、会话结束后，由独立且不带密钥的进程执行。评测结果保存为 `evaluation.json`，不会送回该 Agent 会话。它是本地开发评测，不是正式比赛成绩；预测精度也不等于唯一识别物理源结构。提交后若评测未完成或失败，提交记录仍保留，页面不会凭空生成误差指标。

评测完成后，历史列表、回收站、页头和最终结果显示按赛题第7页公式计算的单宇宙得分，满分100；结果区展开预言分P（80）、定律分L（15）和节约分C（5）。MSE是所有隐藏探针、所有采样时刻的二维位置误差平方和的平均，V是全部无噪真值位置相对总均值的方差。计算 `e=MSE/max(V,1e-12)`、`P=80/(1+10e)`；三个规范声明各正确一项得5分；仅未舍入的P≥40时，`C=5*(1-E/100)`。总分为P+L+C。RMSE仍显示为诊断指标，不另设1e-6的成功阈值，不根据自然语言物理解释质量打分。

题目书面公式采用10e，但旁边数值示例对应5e，两者冲突；工作台按书面公式10e实现，并在公式说明中标注。页面显示分数时的舍入不参与节约分门槛判断。候选无效或超时按题目令P=0，仍可得到声明分；参考真值生成失败、所需历史数据缺失或验证探针不足20条时不伪造总分。未评测、测评中和测评异常分别标示。

新评测直接保存score；旧记录通过 `backfill_scores.py` 根据原验证初态重建V并复用原MSE，在 `evaluation_score.json` 中补存得分，不修改原评测或探索记录，不调用模型或重新拟合。补算文件包含原 `evaluation.json` 的SHA-256，原评测改变后旧分数失效。同世界、版本、配置和评测seed使用固定隐藏案例，不按探索历史换题。当前分数使用本地世界和隐藏验证集，属于按题目公式的本地得分；七世界未定义题目的三级分组，因此不编造九宇宙加权总成绩。

网页导出的是受限的公开快照，包括研究进展、科学记录、预算、提交结果和已生成的独立评测。详情页显示会话启动时选择的推理强度，导出中的 `model_settings` 保存模型、思考开关、推理强度及推理协议配置；旧记录缺失的字段保留为空，不套用当前默认值。原始模型消息和 `reasoning_content` 不通过网页或下载接口暴露。完整原始日志仍按项目原有规则保存在本机运行目录。

## 密钥与本机访问

网页输入的密钥不写入配置文件、日志、浏览器存储或命令行参数，提交开始请求时立即清空输入框。它通过本机 HTTP 请求交给服务，再通过标准输入交给此次独立工作进程；工作进程仅在内存和自己的环境变量中使用，评测前清除。服务读取既有环境变量时，其生命周期仍由启动它的终端管理。网页导出会移除私密字段，并对常见密钥格式脱敏。

服务只绑定 `127.0.0.1` 或 `localhost`，校验实际端口对应的 Host、Origin 和跨站请求标记；启动、停止、删除和恢复接口还需要当前服务的会话令牌。静态资源采用固定白名单，无法通过网页请求任意项目文件。没有开放 CORS，不面向公网或局域网多用户部署。

## 工程验证

HTTP 边界测试用假的运行管理器发送真实本机 HTTP 请求，不调用模型或消耗 API 额度：

```bash
.venv/bin/python -m pytest -q tests/test_web_http.py
```

测试覆盖启动、停止、历史读取、结果下载、历史删除与恢复、运行中删除及恢复冲突错误，以及 Host/Origin/会话令牌、跨站请求、请求体限额、无效或过深嵌套的 JSON、畸形 URL、路径穿越、错误脱敏和禁止公网绑定。测试需要操作系统允许监听临时回环端口。

2026-11-01 验证：加入历史删除与恢复后的 HTTP 边界测试 **58 项通过**，使用本机临时端口和测试管理器，无 API 请求。测试确认新接口不会调用启动或停止方法，并检查冲突状态、异常脱敏及跨站防护。它验证网页通信与边界，不是一次自主发现成绩；自主运行和数值管线的验证另见 [开发验证报告](verification.md)。

同批 HTTP 与后台管理器回归合计 **117 项通过**。浏览器使用独立的临时会话验证了删除当前记录后自动切换、全部删除后的空状态，以及从回收站恢复；没有删除真实探索记录或发出模型请求。

此前完整回归 **187 项通过**；前端 JavaScript 语法检查通过。浏览器中实际验证了配置、启动、运行状态、预算、轨迹和候选结果更新，以及历史展示。真实运行记录汇总保存在开发者本机的 `runs/web-verification.json`，不随 Git 仓库发布。

网页实跑没有伪造成功：`web-20261101-082101-d5333d23` 因单次回复截断结束；`web-20261101-082457-21d4ffc3` 完成拟合与 6 条独立轨迹验证（位置 RMSE 约 5.819e-9），但提交前预算不足；`web-20261101-082647-5d04d8ec` 也因预算不足结束。最后经用户明确批准的一次 300,000 token 上限重试为 `web-20261101-083027-fb2b4310`：实际 15 次调用、237,766 token，候选修订多次未通过表达式检查，下一次请求的保守预算不足，未提交。因此，自动评测的调用顺序已通过工程测试，浏览器可展示既有成功会话的评测；本次网页实跑尚未验证新的成功提交和自动评测。没有以手工提交补齐此结果。

Token 上限同时约束已发生用量和下一次请求的保守预留，因此可能在实际累计值尚未达到上限时停止。大数组、完整历史和反复试错会增加后续请求所需预算；增加预算也不保证自主发现成功。

新会话在已有服务器用量记录、旧消息前缀和工具/模型配置完全相同时，使用已确认的前缀输入 token 数，加上新增消息的 UTF-8 字节上界及 512 token 协议余量预估下次输入。首个请求、改写历史或改变工具/模型配置时回退为完整 UTF-8 上界；不删减消息或思考字段，缓存命中仍按总输入 token 计入。没有可信用量的请求仍保守预留，供应商实际 usage 为最终用量依据。网页显示最近输入的预估与实际值；预算预检阻止新请求时，结束说明列出剩余额度、输入预估和最少输出额度，便于区分实际用尽与无法容纳下一请求。

交互检查中曾意外启动 `web-20261101-083322-1cb8fcd8`，发现后已停止；最后已记录用量为 73,250 token，在途请求用量可能未写入。此记录明确标记为停止，不计作获准重试的结果。随后将启动限定为「开始探索」按钮的明确点击，禁用表单的隐式提交并保留输入有效性检查；不能据此断言自动化误触的具体原因已查明。

结果页可直接用 `/?run=会话编号` 打开已有会话；此链接只读取记录，不启动探索。

### 总预算与单次输出

「Token 总预算」累计一次探索全部模型请求的输入与输出；「单次输出上限」限制一条回复的思考、正文和工具参数。主 Agent 默认分别为 5,000,000 和 65,536，网页允许分别调整至 10,000,000 和 393,216。所有新模型请求均来自主 Agent，调用次数与对话总轮次不设上限。模型调用卡片显示实际次数和“无次数上限”，高级设置不再包含调用上限输入。单次请求超时为 600 秒，整个探索仍受 60 分钟现实时间、总 token 预算、连续无动作回复及每次请求重试上限约束。

旧页面提交的调用上限字段会被忽略，新会话记录有效限额为 `null`。历史会话仍显示其当时的限额及结束原因，不重写旧结果；已有运行进程须按其启动时加载的代码执行，更新后新建探索使用新规则。

供应商报告回复被截断时，框架仍不执行其中的工具指令。只提高总预算不能解除单次上限；下一次请求也必须能放进剩余总预算，实际单次额度可能被预算保护缩小。旧会话保留原始预算，调整设置只影响新会话。
