# 多世界独立评测与一次真实基准

## E1：推理强度消融

`benchmark_reasoning.py` 是单独的 E1 驱动：世界3、4、5 × `low/high/max` × 每格5次，共45次真实自主探索；固定3个并行进程，数值库每进程1线程。以下配置在启动前写入 manifest，不能在批次中途修改：环境种子42、无噪声、5M总预算、393216单次输出、1800秒请求超时、3600秒会话时限、每请求最多1次重试。模型调用次数不限。主提示词、工具和优化器沿用当前版本，不增加反思或研究状态要求。

```bash
.venv/bin/python benchmark_reasoning.py --ask-key --output-dir experiments/E1
```

密钥无回显读取，仅在内存和子进程标准输入中传递。无需网页服务启动；完成并结束独立评测后，会话才移入工作台历史。活动进程在 `runs/.E1-active/`，以免网页误判为中断。请避免同时从网页启动额外探索，以免CPU争用影响数值工具时限。

按5个重复区组预先随机排序，每区组包含9个世界/档位组合。所有尝试均保留，包括失败、超时和未提交，不自动补跑。`Ctrl+C` 停止本驱动的活动子进程，保留原始记录和中断清单；驱动拒绝覆盖或自动续跑同名E1记录。

比较同时报告提交率、完整独立评测率、位置RMSE分布、题目公式得分和终止原因。RMSE < 1e-6仅是预注册的高精度分析标签，不改变工作台评分或宣称官方通过。均分只对有分数的会话计算并列样本数，不能忽略未提交会话选优。每格5次不足以可靠区分相近档位。代码和提示词哈希、配置、执行顺序、实际模型响应版本和原始会话ID都保存在报告中；私有推理与凭证不进入版本库。

下文的 `benchmark_worlds.py` 保留此前七世界基准的固定2M协议，与E1分别记录。

`benchmark_worlds.py` 通过正在运行的本地网页服务为每个已注册世界创建一次真实科研会话，目前共七个世界、顺序执行。会话由同一个 `RunManager` 管理，因此会显示在网页历史中。脚本不会替代模型选公式、补提交、自动重跑、追加预算或删除记录。

先启动本项目的新版网页服务，并在服务进程的环境中配置 `DEEPSEEK_API_KEY`。服务需要使用项目默认的 `runs/` 目录；启动基准时必须没有正在运行的会话。

```bash
cd virtual_physics_law_explore
.venv/bin/python -m shore_agent.web --port 8765
```

在另一个终端启动基准：

```bash
.venv/bin/python benchmark_worlds.py \
  --base-url http://127.0.0.1:8765 \
  --output-dir experiments/my-single-agent-benchmark
```

若服务没有配置密钥，可以增加 `--ask-key`，通过 `getpass` 在终端无回显输入。密钥仅保留在内存，经回环 HTTP 交给服务，不写入参数、配置、报告或日志。不传 `--ask-key` 时可使用服务已有密钥或当前进程的 `DEEPSEEK_API_KEY`。

当前单 Agent 版本的固定协议如下。新探索已移除分析子 Agent 和 summarize_data；历史首轮和扩大预算后的第二轮结果保留原协议，不混入本轮。输出目录必须使用尚不存在或为空的新目录。

| 项目 | 设置 |
|---|---|
| 世界 | `world_1` 至 `world_7`，每个一次 |
| 主模型 | `deepseek-flash`，`thinking=true` |
| 模型调用 | 只有主 Agent；调用次数和对话总轮次不设上限，重试仍计入实际次数 |
| Token 预算 | 每世界 2000000；主 Agent 单次输出 65536；异常请求未知用量的保守预留另外列出 |
| 观察噪声 | 关闭 |
| 仿真随机种子 | 42 |
| 独立评测 | 种子 1871，20 条未见初态轨迹 |
| 其余设置 | 运行开始时的 `config.example.json`；各次必须一致，世界编号除外 |

输出 token 上限、推理强度、超时、优化预算和现实时间上限均由配置文件固定并逐次保存。总 token、现实时间、连续无动作回复和每次请求重试上限继续生效。基准启动前检查配置不含有效的调用或总轮次上限，`max_calls` 与 `main_max_calls` 使用 `null` 表示无限；发现旧限额配置时要求先更新配置，避免记录的配置与实际执行不同。提示词采用当前主 Agent 提示词；脚本记录其 SHA-256，不修改或增加任何正确规律提示。模型名称是供应商管理的别名，相同配置和种子不保证模型回复逐字相同。

每个会话一创建便输出 `run_id`，可在网页和 `runs/<run_id>/` 查看。脚本等待该工作进程及其提交后评测结束，再创建下一个世界。若开始前或两次会话之间有其他活动会话，脚本拒绝继续，不停止其他工作。创建请求失败不会自动重试，以免重复收费。`Ctrl+C` 或 `--wait-seconds` 到期仅停止基准监控，已启动会话保持原样；在网页管理自己的会话。不要用相同输出目录重跑来覆盖失败证据。

报告保存在指定的新目录：

- `manifest.json`：固定协议、世界到实际 run ID 的映射、各次完整公开配置及哈希、主 Agent 提示词哈希、开始结束时间、监控错误。
- `summary.json`：各世界实际状态、原因、API 次数和 token、能量、已提交规律、独立位置/速度 RMSE、会话现实耗时及含评测耗时。
- `comparison.md`：上述核心指标的并列表。

`completed_all_attempts` 只表示全部计划均结束，不表示发现了正确规律。`incomplete`、`error`、停止和评测失败保留在比较中。只有真实受理且结束的提交可关联独立评测；缺少 RMSE 使用空值，不写成零。没有预先规定误差阈值，所以不会把低误差自行宣称为官方通过。已提交规律的等价预测能力也不证明作用源结构唯一。

## 独立评测

`evaluate.py` 仅在会话已持久化唯一一份 `accepted` 且 `session_ended=true` 的提交后运行。它先核对配置与任务中的世界编号，再访问该世界独立真值轨迹。旧记录缺省世界为 `world_1`；身份冲突拒绝评测。评测不重拟合参数，不向已结束的科研 Agent 反馈真值。

```bash
.venv/bin/python evaluate.py --run-dir runs/<run_id> --seed 1871 --n-probes 20
```

当前 `physics_version=v4`：世界一使用解析轨迹，世界二使用矩阵指数，世界三至七使用更高精度的独立 Radau 积分。v4评测为冻结规律提供瞬时可见天体状态；具体输入契约见[世界说明](worlds.md)。历史无版本会话按 `v1` 处理，旧世界五仍使用矩阵指数；配置和任务的版本冲突会拒绝评测。报告 `truth_reference` 明确区分这些参考方法；数值参考不声称解析精确。出现候选推演或真值参考数值失败时，整体误差为空，另列失败条目及成功子集指标。按题目公式计分时，候选预测无效的预测分 P 为 0，规律声明分仍单独计算；真值参考失败则标记无法计分，不能当作 Agent 的零分。评分公式与边界见[网页使用说明](web.md)。

## 离线验证

```bash
.venv/bin/python -m pytest tests/test_benchmark.py tests/test_numerics.py -q
```

驱动测试使用明确标注的 mock 服务和临时目录，验证全部世界各一次、不重跑、密钥边界、错误统计、配置核对和报告。评测测试使用独立 oracle 验证世界路由与身份拒绝。这些测试不代表模型自主发现成功，也不会调用真实 DeepSeek API。

扩大预算后的实际结果见 [第二轮报告](five-worlds-large-budget-results.md)；首轮原始记录保持不变。

与旧版对照时，注意世界定义、观测协议、工具集和主提示词的版本差异。历史单Agent批次曾将主Agent调用上限从20调整为24；当前新运行已取消调用次数和总轮次限制，历史报告中的限额保持原样。单世界一次试验不能估计稳定成功率；比较结果应保留这些协议差异，不称为只改变一个变量的严格消融。
