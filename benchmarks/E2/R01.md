# E2 R01：开放 Python 分析能力是否有帮助

30个计划单元完成：原工具组高精度成功 **12/15**，增加 `run_code` 组 **13/15**。高精度指完整独立评测位置 RMSE < 1e-6；代码执行成功与高精度成功分别统计。

## 实验设计与额度中断

世界3、4、5，每组各5次。两组均为 DeepSeek Flash、thinking=true、high 推理强度、5M总Token、单次输出上限393216，无模型调用次数上限。每会话3600秒，固定3并发、数值库单线程。环境v4、seed=42、无噪声、固定天体布局；每个提交使用20条独立隐藏轨迹、seed=1871评测。E1没有作为控制组复用。

原工具组保持原始main.txt和7个工具；代码组只增加可选run_code及必要接口说明，没有新增强制反思、进度或研究状态更新步骤。代码每次在无网络、无宿主挂载的Docker容器执行，最多1CPU、1GiB、90秒。最终仍通过正式拟合、验证、submit提交受限表达式。

首批30次中9次正常完成，21次被账户HTTP402中断（其中18次没有得到模型回复）。用户恢复额度并授权继续后，只对21个402单元从新会话补跑，配置、提示词、源代码、镜像不变；保留原9次，包括已经完成的科学失败。因此共留存51次实际尝试，主表是**额度恢复后30个计划单元的结果，不是首批一次运行成功率**。补跑时恢复完整会话预算，原中断消耗单列。此调整在补跑前写入 recovery-1/manifest.json；不重跑科学失败或预算失败。

首批完整结果见[summary.json](summary.json)与[comparison.md](comparison.md)，恢复后的主结果见[combined_summary.json](combined_summary.json)。后者每行标注原尝试编号和是否补跑。

## 代码实际新增了什么

原fit工具也能拟合Agent给出的具体表达式。run_code新增的是**主Agent自己选择数据处理、候选比较和数值分析算法并实际执行**；不是证明原工具绝对不能发现相同规律。以下来自公开代码和结果，源码、输入引用与后续调用见[code_audit.json](code_audit.json)。

1. **世界3：按源点构造基函数并成批比较。** `E2-code-w3-r1 / code_655439848d03`对齐加速度估计时间与位置，比较逐源线性项、三次径向项、各天体系数、额外高次项等，估计共享系数约0.059996和0.00399983。后续正式轨迹拟合、验证及隐藏评测达到1.13e-7。这里的初估来自差分加速度，最后精度来自正式整条轨迹验证。

2. **世界4：自写核函数比较与多初值搜索。** `E2R1-code-w4-r2 / code_3cfd69ca9678`比较`g·d/(|d|²+s²)^(p/2)`、固定p=2/3、无软化及分源系数。差分数据上的自由指数约3.087，固定p=3误差约0.00592，p=2约0.0529；这提供候选选择证据，不应把初估当最终精确参数。该会话隐藏RMSE为7.96e-8。

3. **世界5：提取速度耦合并比较空间核。** `E2-code-w5-r1 / code_2ca2f3297d4a`从空间网格轨迹中扣除位置回复项，估计随位置变化的旋转系数；`code_ca96415870fd`在444个状态样本上批量比较指数、Gauss、逆一次和逆二次软化核。逆二次核的系数约0.9999、长度尺度约0.9978；x分量差分加速度RMSE约0.00145，优于该次指数核0.00215。随后law_1正式拟合得到k≈0.1、c≈1、e≈1，隐藏RMSE为7.37e-8。代码让这些定量比较成为可执行操作。

上述先后关系证明工具提供了可用计算结果，并记录了后续候选；不能单独证明某个代码调用造成成功。组间结果衡量的是“增加代码能力及接口说明”的整体效果。

## 失败与改进线索

**原工具世界3三次提前接受了近似模型。** `E2-baseline-w3-r1`、`E2R1-baseline-w3-r3`、`E2R1-baseline-w3-r5`采用平移中心的各向异性三次回复近似，隐藏RMSE分别为0.10418、0.09189、0.05309；训练RMSE已经约0.00136、0.00330、0.00184，验证也非数值精度级。三次结束时仍剩70/87/64能量、约3040/3241/2888秒，因而不是额度耗尽。真实结构是对各源点的`Σ_b (0.06+0.004|b−r|²)(b−r)`，上述受约束中心形式没有正确表达全部空间项。

**代码组世界5第4次分析过久，最后才找到正确核。** `E2R1-code-w5-r4`用了35次模型调用、4,876,865 Token。下一次请求估计输入290,620 Token，大于剩余123,135，因此在调用前停止；这不是单次输出截断，也不是API再次402。该会话先重复线性/多项式、纯逆距离和隐源分析，早期两次忘记把逻辑放入analyze(inputs)，又有一次输入别名数量超限。末次`code_9115eed1e198`已比较出`Σ1/(d²+a²)`且系数/尺度接近1，但来不及重新正式拟合、验证、提交。它保留为未完成，不能因末次结果接近真值而算成功。

**代码组世界5第5次算了很多，却选中了错误核。** `E2R1-code-w5-r5`进行27次代码执行、38次模型调用，最终提交指数核`Ω(r)=p4+p2·Σexp(−|b−r|/p3)`。训练位置RMSE为0.01286，最后独立验证为0.01716，隐藏评测为0.12386。代码比较了纯逆距离、平方根软化和指数核等，但没有完成对正确逆二次软化结构的确认。当时仍剩77能量和约2621秒；这次是候选选择与停止判断失败，不是容器故障或预算耗尽。不少代码仅返回`{"ok":1}`，实质数值写在stdout；执行成功本身没有给候选选择增加保证。

后续优先改进方向是：让代码默认返回小型比较表与必要诊断，把大数组留为产物或可回调记录；明确输入别名与analyze(inputs)契约；减少不断增长的会话重复携带已有数值数据。这些可以减少重复和上下文膨胀，但本次没有边跑边修改，也没有为代码组增加额外预算。本次不引入子Agent、不强制输出研究状态或进度。

## 结论边界

保留run_code作为可选能力是合理的：新增的数据变换和批量数值比较确实被使用，世界3出现收益；但它没有保证成功，也没有证明在每个世界更快。工作台默认仍关闭，由高级设置开启。不要把本次小样本结果理解为代码组普遍优于原工具组。

- baseline总体成功率Wilson 95%区间约 54.8%–93.0%。
- code总体成功率Wilson 95%区间约 62.1%–96.3%。

每世界每组只有5次，固定布局、同一环境种子和隐藏集，重复主要测模型随机性；不覆盖噪声、跨布局泛化或其他模型。两批跨越额度恢复，提供商管理的模型别名并非固定权重。HTTP状态、返回model及system_fingerprint均记录在diagnostics.json，不能据此保证提供商内部版本完全不变。
