# E2 R02 案例与接口改进的边界

本轮15次代码组全部提交，并在完整20条隐藏轨迹上达到位置RMSE<1e-6。世界3、4、5分别5/5；不存在用补跑替换科学失败。以下分析只使用公开工具调用、执行记录、拟合、验证和评测结果。

## 接口摩擦减少，但计算错误没有消失

上一批E2 R01代码组170次调用有35次未成功（20.6%）；本批176次调用有21次未成功（11.9%）。此前8次脚本入口约定错误、2次输出schema错误和1次科学数据类型序列化错误，在本批相应类别均为0。

这不是完全同口径的能力提升：本批155次执行成功中，124次带有“未设置结构化result”的提示，允许只通过print返回信息。以前缺少analyze函数会失败，现在普通脚本可以完成同样的计算。E2 R01的纯print提示次数为0，只表示旧接口没有这种提示，并不表示旧代码从不使用print。

本批仍有16次数值或代码错误、2次工具参数校验失败、2次计算超时和1次执行环境协议错误。普通脚本接口不替模型修复矩阵奇异、数组形状、索引或错误字段；错误行和输入形状用于减少定位成本。

模型收到的工具返回JSON中位大小从5240降至1446.5字节，减少约72.4%。不再重复返回代码与schema是实现直接保证的变化；这不等于总上下文或计费Token下降同样比例，先前请求中的代码仍在历史里。按字段读取本批只使用2次，尚不足以说明模型已充分利用选择性读取。

## 世界5第4次：成功，但仍绕了很长的路

会话`E3-code-w5-r4`耗时1096.5秒、消耗4,952,395 Token，已接近5M上限。它调用30次run_code、投放9批探针，经历2次计算超时与2次代码错误，最终进行了2次正式拟合、2次独立验证并提交。

公开分析涉及多项式、中心位置和速度耦合核等候选。第一个正式候选的速度旋转系数采用软化反距离核：

```text
Omega(x,y) = W0 + C * sum_b(1/sqrt((x-bx)^2+(y-by)^2+eps^2))
ax = -k*x + Omega(x,y)*vy
ay = -k*(y-cy) - Omega(x,y)*vx
```

它的训练位置RMSE约5.10e-4，独立验证RMSE约0.799，未泛化。第二个候选把核改为`1/((x-bx)^2+(y-by)^2+eps^2)`，拟合得到k约0.3、cy约1、C约1、eps约1、W0约0，训练RMSE约3.25e-9，独立验证约1.81e-8，最终隐藏RMSE为2.73461744e-7。

这说明验证工具仍在纠正错误候选，简化接口也没有消除长时间探索错误函数形式的问题。不能断言此次成功是返回压缩造成的；跨批次模型决策不同，没有同轨迹的因果对照。

会话`E3-code-w3-r4`中的`code_818a9189fe60`执行自编积分分析时触及截止时间，随后Docker kill操作等待8秒仍超时，记录为`protocol_error / TimeoutExpired`，总耗时约108.1秒。没有足够证据把该异常归因于数学代码本身。事后检查对应容器已不存在，没有遗留运行容器。

该异常完整保留，Agent随后继续探索，最终隐藏RMSE为6.16346180e-7。它计入代码工具未成功调用，但不应把整个会话算作探索失败。

## 代码仍能承担额外分析

`E3-code-w5-r2`的`code_4c28f6b53d53`利用已取得轨迹计算能量量的变化，最大差约3.13e-9，并通过stdout返回。它展示了普通脚本可完成原固定工具未直接提供的守恒量数值检查；这只是已观测轨迹上的证据，不构成所有初态的守恒证明。

网页已实际查看该会话的精简代码返回：显示计算输出、缺少结构化result提示和读取引用，没有重复整段代码/schema；该检查未启动新的探索。

## 当前结论

保留简化后的可选run_code接口是合理的：减少格式约束和重复返回，未改变正式拟合、验证、提交链。本轮15/15支持这一实现可用，但每世界仅5次、固定布局和固定隐藏集，不能证明普遍稳定成功，也不能仅靠E2/E3跨批次差异估计因果收益。本轮不再追加原工具组或补跑。
