# E2 R04：统一当前会话文件读取

**状态：工程实现与回归完成，未运行新的真实探索。** 用户选择只开放当前探索会话的数据，不开放历史独立会话。本轮取消专用记录回读接口，让模型按文件路径选择数据。

## 修改

1. 删除模型工具`call_back`，增加`list_files(path, offset, limit)`和`read_file(path, offset, limit)`。文本按字符分页，返回总长度、下一页偏移和完整文件SHA256；二进制文件由代码读取。
2. 首次任务包列出已有文件，新观测、拟合、验证等结果附`workspace_files`。文件目录包括`observations/`、`laws/`、`validations/`、`residuals/`、`submissions/`及`analyses/<execution_id>/`，后者包含代码、结果、日志和导出产物。
3. `run_code`只要求`code`，可选`files`路径列表，省略表示不加载文件。脚本通过`read_json(path)`、`read_file(path)`、`read_bytes(path)`读取所选文件完整快照，通过`available_files`查看已加载路径；无需先让模型分页读取再抄写数据。最多128个文件、合计16MiB。
4. 这是当前会话的虚拟文件接口，路径不是宿主文件路径，也没有挂载为容器原生文件；脚本须用上述读取函数，不能用`open(虚拟路径)`。原有`output/`仍用于导出产物。底层执行器保留旧inputs兼容能力，当前模型schema和提示词只公开code/files协议。
5. 允许读取的文件由当前会话已取得记录登记，不扫描runs目录。其他会话、源码、配置、密钥、模型消息和隐藏评测不登记。路径穿越、绝对路径、未登记文件被拒绝；产物检查名称、大小、符号链接及SHA256。
6. 代码输入快照与路径、哈希、字节数一起归档到`code_executions/<id>/input_files.json`及执行记录，可追溯实际输入。继续使用R03的`probe_arrays`和显式时间对齐；不修改科学规律、拟合、验证及提交要求。前端增加浏览、读取文件的中文日志。

默认工具从7个变为8个，启用run_code后为9个。历史E1/R01/R02的冻结工具组保持原始记录；后续比较须重新说明使用的接口版本。

## 使用例子

模型可调用`list_files`浏览当前会话，再调用`read_file`查看文件片段。若直接计算，调用run_code时传入：

```json
{
  "files": ["observations/probe_0001.json"],
  "code": "p = read_json('observations/probe_0001.json')\ns = probe_arrays(p)\nresult = {'times': s['t'], 'positions': s['r']}"
}
```

上述路径需已在本会话取得；工具不会为缺失数据自动投放探针或读取其他会话。


结果：**748 passed，78.88秒**。包括真实Docker执行、原有科学工具回归，以及新增检查：

- 当前会话目录和文本分页可完整重建，Unicode及SHA256一致。
- 其他会话同编号记录、未登记磁盘文件、隐藏评测、宿主路径和路径穿越不可读。

- run_code读取完整快照，来源哈希与read_file一致；重复JSON读取互不污染。
- 真实容器可用新读取函数及probe_arrays，未选择的文件不可读。
- 旧call_back和模型层inputs参数被拒绝，原有模型循环正常工作。
