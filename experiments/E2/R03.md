# E2 R03：简化可选输入与数据读取

**状态：工程实现与回归验证完成，尚未运行新的真实探索。** 本轮只落实R02失败分析中的前两项：inputs可省略，以及减少手工读取、抄写和拼接数据。没有新增科学成功率结果，不把测试通过等同于探索改善。

## 修改

1. `run_code`只要求code。省略inputs等价于空对象；显式null或错误结构仍被拒绝。代码需要观测时，仍通过记录类型/编号显式传入，不自动加载所有会话数据。
2. 仅启用代码工具时，在首次任务包及新取得的探针/天体观测中附加code_inputs，列出实际记录编号、字段名、形状及字典键；同布局记录分组以减少重复。首次任务包元信息随原始任务包冻结，后续观测不会改写它。
3. 脚本获得input_info和get_record(alias,id)，读取本次加载的原始记录；缺失编号时明确返回实际可用编号。保留原inputs列表接口。
4. probe_arrays(record)提供观测时间轴上的t/r/v；time_axis="acceleration"则使用a_est_times并返回t/r/v/a。默认要求精确时间匹配，拒绝缺失字段、错误长度、非有限值、非递增时刻；不截短、不补零。只有显式interpolation="linear"才插值r/v，禁止外推，返回alignment说明。a始终为原差分估计，不是真实加速度。
5. 提示词说明实际天体字段times/body_ids/positions_obs，提醒天体可能运动。原始记录、输入引用与哈希继续归档；工具不替Agent选公式或修复算法。

未修改候选异常处理、容器超时逻辑、正式拟合/验证/submit或原7工具schema。没有增加子Agent、自动改代码重试或模型调用。

## 使用例子

无数据引用的计算可以仅传：

```json
{"code": "result = 1 + 1"}
```

引用实际记录时，仍传inputs，例如`{"probes":{"record_type":"probe","record_ids":["probe_0001"]}}`，代码为：

```python
p = get_record("probes", "probe_0001")
s = probe_arrays(p, time_axis="acceleration")
result = {"times": s["t"], "positions": s["r"],
          "velocities": s["v"], "estimated_acceleration": s["a"],
          "alignment": s["alignment"]}
```
