# E5：在 300 秒和 4096 token 内恢复无噪声六世界基线

目标是在**同一批六个世界**中至少五个取得本地分数 ≥90，同时每场探索不超过 300 秒、每次模型调用输出不超过 4096 token。E5 继续严格保留 10 能量；探索观测先关闭噪声，独立测评始终使用无噪声轨迹。R01 达到 3/6，R02 达到 2/6，均未达到目标；R03 正在运行，结果待归档。

这是 v15 六个公开开发世界上的自主探索和本地适配器评测，不是正式赛事成绩。每批每世界只运行一次，不自动重启会话、不恢复上一场探索，也不跨批挑选最好分数拼成一轮。90 分是本次用户设定的复现目标，不是官方通过线；达标判断使用未四舍五入的原始分数。

## 计时与 token 口径

- **探索耗时**从首次 mission 开始，包含模型调用、科学工具、提交检查与会话收尾；300 秒限制针对探索阶段。有效提交或保存配对必须在截止前通过检查，截止后的封存不能进行新推理、拟合或补写声明。
- **总耗时（含评测）**采用每个 worker 的实际墙钟时间，包含启动/收尾及独立评测，不含等待空闲模型端点的排队时间；因此不等于探索耗时与评测耗时的简单相加。独立评测在探索结束后进行，不占探索的 300 秒。
- **平均输出 token/调用**为 API 报告的 completion tokens 总和除以模型调用数；最大输出检查每一次请求，不以平均值代替 4096 上限。截断调用也计入耗时、调用数及 token。
- 四卡并行后，整批墙钟时间、六个 worker 总耗时之和、单场 300 秒限制是三个不同口径。

相对 R01 只调整两项：

1. 每场允许一次长度截断恢复。保留原始审计日志，丢弃截断回复，不执行其中的工具调用、不补全残缺 JSON，再要求模型给出完整下一步。恢复调用仍计入原场次的时间及 token；不重开 300 秒，也不提高 4096 上限。

日志揭示的具体问题如下；这些是探索记录的事后诊断，未向运行中的 Agent 回传测评答案。

- **world_2：属性未覆盖，低残差产生错误信心。** 两条免费和六条付费探针的 mass、charge 都为 1。候选在固定属性上的独立验证位置 RMSE 约为 `1.40e-11`，但没有实验辨识属性作用，公式未包含属性依赖，25.39 秒即提交。其 25.65 分说明局部验证误差小不代表适用范围完整。
- **world_3：截断恢复有效，候选表达仍错误。** 第 5 次调用触及 4096 token 后完成一次安全恢复，最终成功提交；但模型尝试过超出参数约束的表达式，之后把两个轴的位置部分写成同一组系数，无法表示一般二维向量关系。最终提交候选训练位置 RMSE 约 `0.1886`；此前同结构候选的验证 RMSE 约 `0.2574`，仍未转向能解释系统残差的结构。恢复解决的是会话中断，不保证物理推断正确。
- **world_5：把无噪声下的系统残差当成足够精确。** 多次源叠加候选失败或触及 25 秒拟合上限后，提交简化的两轴模型；最终训练位置 RMSE 约 `0.03966`。模型已指出部分运动方向存在系统偏差，仍称总体误差很低并提交。短时或局部验证没有覆盖完整结构，独立测评分数为 27.04。
- **world_6：仍有明显验证误差，绝对时刻覆盖不足。** 成功取得的付费探针均在 `t0=0`，虽然跨度扩大到 8–10 个物理时间单位，但未进行不同投放时刻的控制实验。最终候选验证位置 RMSE 约 `0.4765`，仍因已有可提交草稿而结束，得分 21.64。草稿检查通过不能代替物理验证。

R02 的 world_4 恢复高分，但 world_2、world_3 相对 R01 退步，表明通用文字提醒的执行仍不稳定；不能把 R01 的高分世界替换到 R02 里宣称提升。
