# E4：300 秒 / 10 能量的六世界基线

配置冻结后，在 qz-infer 四张卡上使用四个独立 Qwen3.8-27B BF16 实例，关闭思考，六世界各进行一次新探索。一个端点仅一个活跃世界；队列与预热在 mission 之外。

本轮只实施已确认的前三项：统一 E4 规则；硬截止与模型显式保存的有效草稿；推理图执行、prefix cache 和单卡单活跃调度。没有历史压缩、科学候选模板、答案注入、整场自动重试或三轮限制。

- 环境：v15 六个公开开发世界，seed=42，位置/速度读数噪声开启。
- 预算：10 能量；首次 mission 开始后 300 秒；每调用最多 4096 输出 tokens；累计 5M tokens。
- 及时的明确 law_id + claims 草稿可封存；未形成有效配对则记录未完成，不生成成绩。
- 探索、交卷后独立评测和含评测总耗时分别记录；每轮平均输出同时附单次最大输出，未知 usage 不伪造。
- 仍使用现有本地候选/积分协议，并非正式 SDK，不代表官方比赛成绩。

服务配置微基准见 [service-ab.json](service-ab.json)：固定 19,426 输入 / 256 输出 tokens，旧 eager/no-cache 服务约 16.16 秒，优化后热缓存约 4.10 秒。联合改变了缓存、图执行和并发设置，不能拆分因果，也不能当作六世界加速倍数。

旧规则服务器批次已完整归档为 [E3](../E3/README.md)。

## 剩余耗时分布

模型请求合计591.93秒，占探索总时长 **77.7%**；科学工具166.13秒，占 **21.8%**；剩余3.64秒是日志等未归属部分。没有逐调用首token时间，不能把请求总耗时继续拆成排队/prefill/decode。

- 世界1、2、4、5主要耗时仍在模型请求（约84.22、106.83、160.29、85.12秒）。
- 世界3的拟合累计75.07秒；世界6的拟合累计84.57秒。多次拟合达到约25秒单次上限，成为这两个世界的主要开销之一。
- 本批没有触发300秒截止，也没有依靠4096截断结束请求；五个世界调用过save_draft，但最终六个世界均为模型主动submit，不能把本批的完成率归功于超时草稿兜底。

本轮先保留这版基线，不继续改变科学搜索策略、拟合目标或历史长度。
